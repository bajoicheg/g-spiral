# G-Spiral v1.2.0 — спецификация релиза

**Статус:** согласовано к реализации  
**Целевая версия:** `1.2.0`  
**Платформа:** Windows 10/11 x64  
**Формат поставки:** portable self-contained single-file `G-Spiral.exe`, без инсталлятора  
**Базовая версия:** G-Spiral 1.1.0

---

## 1. Цель релиза

Версия 1.2.0 меняет саму механику прохождения опроса. Пользователь больше не выбирает одну из шести готовых карточек, напрямую связанных с типами корпоративной культуры. Вместо этого исходная матрица 6 × 7 превращается в скрытую систему атомарных утверждений.

Пользователь проходит опрос **в 7 этапов по столбцам исходной таблицы**, как и в версии 1.1.0. На каждом этапе он видит название текущего столбца, но не видит, к какому из шести типов относится каждое утверждение. Все утверждения внутри этапа перемешиваются в случайном порядке.

Итоговая цель — снизить возможность осознанно подгонять ответы под желаемый цвет/тип и получить более детальный профиль корпоративной культуры.

## 2. Сохраняемые возможности версии 1.1.0

В версии 1.2.0 без изменений сохраняются:

- portable-модель, без установки;
- Windows 10/11 x64;
- self-contained `.NET 8` single-file EXE;
- работа без Microsoft Excel;
- отсутствие телеметрии и сетевых обращений;
- автоматическое получение имени из `Environment.UserName`;
- автоматическое получение компании из `Environment.UserDomainName`;
- возможность отредактировать имя и компанию;
- локальное хранение состояния только в памяти;
- формирование XLSX через Open XML;
- действия «Открыть файл» и «Открыть папку» после сохранения;
- возможность изменить имя и компанию после прохождения без потери ответов;
- цветовая система итоговых типов;
- клавиатурная навигация и accessibility;
- имя файла отчёта: `Spiral_<Имя>_<Компания>_<yyyy-MM-dd>.xlsx`.

## 3. Структура методики

### 3.1. Скрытая матрица

Внутренняя модель по-прежнему состоит из 6 типов × 7 тематических столбцов = **42 скрытых квадратика**.

Канонический порядок типов: Бирюза, Возможности, Успех, Правила, Сила, Принадлежность.

Этапы: Атмосфера; Система управления; Убеждения; Слоган; Лидер; Какие потребности рядового сотрудника удовлетворяет; В каких условиях эффективна.

### 3.2. Атомарные подпункты

Каждый из 42 квадратиков содержит **от 3 до 6 отдельных выбираемых подпунктов**. Каждый подпункт представляет достаточно атомарную характеристику, которую пользователь способен оценить независимо от соседних характеристик.

Если исходная формулировка квадратика содержит менее 3 самостоятельных пунктов, она разбивается на 3–6 более атомарных утверждений без изменения исходного смысла. Нельзя переносить смысл из одного квадратика в другой или менять скрытую принадлежность утверждения к типу/столбцу.

## 4. Новый сценарий прохождения

### 4.1. Стартовый экран

Сохраняются название G-Spiral, заголовок «В какой компании ты работаешь?», редактируемые поля «Имя» и «Компания», краткое описание семи этапов, кнопки «Начать» и «О программе». Имя и компания должны быть заполнены.

### 4.2. Опрос строго по этапам-столбцам

Опрос состоит ровно из 7 страниц. Вверху: `Вопрос N из 7`, крупный заголовок текущего столбца, инструкция и прогресс. Под заголовком — единый список всех атомарных утверждений текущего столбца.

### 4.3. Пул вариантов этапа

В пул этапа входят подпункты из всех шести скрытых квадратиков данного столбца. При 3–6 подпунктах в квадратике страница содержит ориентировочно 18–36 вариантов.

Запрещено раскрывать скрытый тип через группировку, цвет, название, tooltip, accessibility metadata, порядок, иконку, форму, рамку или размер.

### 4.4. Рандомизация

1. Для каждого этапа при старте создаётся отдельная случайная перестановка.
2. Порядок фиксируется на всё текущее прохождение.
3. «Назад» не меняет порядок.
4. «Пройти заново» создаёт новый порядок.
5. Рандомизация не влияет на баллы.
6. Декоративная раскраска не вычисляется из скрытого типа.
7. Для тестов поддерживается детерминированный seed.

### 4.5. Выбор

На каждой странице можно выбрать от 0 до всех подпунктов. «Далее» разрешено при нуле. Показывается `Выбрано: N из M`. Есть «Снять всё» и «Выбрать всё» для текущего этапа.

## 5. Визуальный дизайн

Интерфейс остаётся цветным, современным и визуально богатым, но цвета этапа исключительно декоративные и не кодируют типы. Подпункт — отдельная кликабельная карточка/чип. Выбранное состояние имеет насыщенную подложку, галочку, усиленную рамку и остаётся понятным без восприятия цвета. Для 18–36 пунктов используется прокручиваемая адаптивная сетка 2–3 колонки, footer навигации всегда доступен.

## 6. Система баллов

Каждый скрытый квадратик имеет максимум **100 баллов**. Формула:

`CellScore = 100 × SelectedCount / OptionCount`

Внутренняя математика не округляется. Тип суммирует 7 своих ячеек:

`TypeScore = Σ CellScore`, диапазон `0…700`.

Итоговый абсолютный процент:

`TypePercent = TypeScore / 42`

что эквивалентно `TypeScore / 4200 × 100%`. Максимум одного типа = 16,666…%; при полном выборе всех 42 ячеек сумма шести типов = 100%. В UI/XLSX процент показывается до 0,1%.

## 7. Финальный экран

Финал содержит идентификацию, отсортированные результаты, 3D-круговую диаграмму, блок «Ваши ответы», действия XLSX, возврат к ответам, изменение имени/компании, «Пройти заново» и «О программе».

Сортировка: по `TypeScore` убыванию, затем канонический порядок.

Для каждого типа: название, итоговый цвет, `x / 700`, абсолютный процент, горизонтальная шкала.

### 7.1. 3D pie chart

Бублик заменяется 3D pie chart. Сектора строятся по относительной доле `ChartShare = TypeScore / Σ TypeScore`; таблица рядом показывает абсолютный `TypePercent`. Подпись: **«Структура выбранных соответствий»**. При нуле диаграммы нет и показано «Нет выбранных соответствий».

### 7.2. Ваши ответы

По всем 7 этапам показываются название, число выбранных вариантов и выбранные утверждения. Скрытый тип подпункта здесь не раскрывается.

## 8. XLSX-отчёт

Итоговый XLSX содержит **3 вкладки**.

### 8.1. `Выборы`

По каждому этапу: название, полный набор атомарных подпунктов, выбранные отмечены `✓` и ярко выделены, невыбранные приглушены. Порядок сохраняется таким, каким был показан пользователю. Скрытая принадлежность к типу не показывается. В шапке: респондент, компания, дата/время, версия.

### 8.2. `Таблица ответов`

Полная матрица 6×7. Строки — шесть типов, столбцы — семь этапов. Каждая из 42 ячеек содержит все свои атомарные подпункты, `✓`/`○`, балл ячейки `x.x / 100`; выбранные ярче, невыбранные приглушены. Здесь скрытая принадлежность раскрывается, так как отчёт формируется после тестирования.

### 8.3. `Итоги`

Столбцы: `Место`, `Тип организации`, `Баллы`, `Максимум`, `Итоговый процент`. Таблица отсортирована по убыванию. Рядом — 3D pie chart с каноническими цветами типов. При полном нуле вместо диаграммы — «Нет выбранных соответствий».

### 8.4. Оформление

Фирменный стиль, wrap text, разумные ширины, freeze panes, landscape/fit-to-width где нужно, footer `Сформировано G-Spiral 1.2.0`.

## 9. О программе

Кнопка доступна минимум на стартовом и итоговом экранах. ## 10. Состояние и повторное прохождение

«Назад» сохраняет ответы, имя, компанию, случайный порядок и декоративные цвета. После изменения ответа/имени/компании ранее сохранённый XLSX считается устаревшим. «Пройти заново» очищает ответы, возвращает Windows username/domain и генерирует новый случайный порядок.

## 11. Модель данных

Рекомендуются `SurveyStageDefinition`, `CellDefinition`, `AtomicOptionDefinition`, `SurveyRunState`. Скрытые `CultureTypeId` и `CellId` не попадают в пользовательскую разметку этапа.

## 12. Тестирование

Проверить каталог (6 типов, 7 этапов, 42 ячейки, 3–6 подпунктов, уникальные ID), рандомизацию, стабильность Back, новый порядок Restart, независимость декоративных цветов, формулы scoring, all-cells=4200, сумма процентов=100% при полном выборе, сортировку/tie-break, отсутствие скрытых типов в вопросном UI.

XLSX: ровно 3 вкладки `Выборы`, `Таблица ответов`, `Итоги`; Open XML Validator без ошибок; identity/version; 42 ячейки аудита; выбранные подпункты; правильные cell scores; сортировка; 3D pie при ненулевом результате; отсутствие диаграммы при нуле; правильная палитра.

CI: restore, tests, Release build, win-x64 self-contained single-file publish, `G-Spiral.exe --smoke-test`, artifact upload и GitHub Release для `v1.2.0`.

## 13. Критерии приёмки

Релиз готов, если опрос идёт по 7 столбцам, заголовки сохранены, в 42 ячейках по 3–6 атомарных вариантов, внутри этапа единый случайный пул, принадлежность скрыта, выбирается 0..all, scoring использует `100 × selected / total`, типы суммируют 7 ячеек, абсолютный процент = `TypeScore / 42`, результаты отсортированы, финал показывает ответы и профиль, 3D pie заменяет бублик, XLSX содержит три требуемые вкладки и аудит 6×7, есть «О программе» с `© 2026 V. Vasilev`, приложение остаётся portable/offline, все тесты и smoke проходят.
