# G-Spiral — дизайн приложения и XLSX-отчёта

Дата: 2026-09-16  
Репозиторий: `bajoicheg/g-spiral`

## 1. Цель

Создать автономное Windows-приложение `G-Spiral.exe` для опроса «В какой компании ты работаешь?» по типологии корпоративных культур из предоставленной пользователем таблицы.

Приложение должно:

- запрашивать название компании;
- проводить 7 последовательных вопросов;
- в каждом вопросе показывать 6 вариантов, соответствующих 6 типам организации;
- разрешать выбрать от 0 до 6 вариантов в каждом вопросе;
- подсчитывать суммарное число совпадений по каждому типу, максимум 7;
- показывать итоговый экран с рейтингом и диаграммой-бубликом;
- сохранять результат в `.xlsx` с двумя листами: `Выбранные опции` и `Итоги`;
- работать без инсталлятора, без установленного Excel, Python и отдельно установленного .NET Runtime;
- не использовать сеть, телеметрию, реестр или локальную БД.

## 2. Технологический стек

- .NET 8
- WPF
- `win-x64`
- self-contained publish
- single-file executable
- Open XML SDK для генерации XLSX
- xUnit для автоматических тестов
- GitHub Actions на Windows runner для CI и сборки portable EXE

Итоговый исполняемый файл: `G-Spiral.exe`.

## 3. Архитектура

Приложение разделяется на четыре логические части.

### 3.1. Survey UI

Отвечает только за взаимодействие с пользователем:

- стартовый экран с названием компании;
- 7 экранов-вопросов;
- навигация `Назад` / `Далее`;
- экран результатов;
- диалог сохранения XLSX;
- обработка понятных пользовательских ошибок.

### 3.2. Survey Model

Содержит:

- канонический набор 7 вопросов и 42 вариантов;
- 6 типов организации;
- точную цветовую палитру;
- ответы пользователя;
- правила подсчёта;
- стабильную сортировку итогов.

Бизнес-логика не должна зависеть от WPF или Open XML, чтобы её можно было тестировать отдельно.

### 3.3. Results UI

Показывает:

- название компании;
- 6 типов, отсортированных по убыванию совпадений;
- число совпадений в формате `x из 7`;
- горизонтальные полосы результата;
- диаграмму-бублик в цветах типов;
- кнопки `Сохранить XLSX`, `Назад к ответам`, `Пройти заново`.

Промежуточные баллы во время прохождения опроса не показываются.

### 3.4. Excel Export

Формирует один автономный `.xlsx` без COM Automation и без зависимости от установленного Excel.

Экспортёр должен быть отдельным компонентом с тестируемым входом: название компании, ответы, рассчитанные результаты.

## 4. Пользовательский сценарий

### 4.1. Старт

Экран содержит:

- название приложения;
- вопрос `В какой компании ты работаешь?`;
- текстовое поле названия компании;
- кнопку `Начать`.

Пустое или состоящее только из пробелов название не принимается.

Название компании используется:

1. на экране результатов;
2. в шапке обоих листов XLSX;
3. в предлагаемом имени файла.

Предлагаемое имя:

`Корпоративная_культура_<Компания>_<yyyy-MM-dd>.xlsx`

Недопустимые для имени файла символы очищаются только в имени файла. Исходное название внутри отчёта не изменяется.

### 4.2. Вопросы

Всего 7 вопросов:

1. Атмосфера
2. Система управления
3. Убеждения
4. Слоган
5. Лидер
6. Какие потребности рядового сотрудника удовлетворяет
7. В каких условиях эффективна

Каждый вопрос показывает 6 карточек, по одной на каждый тип организации.

Пользователь может выбрать:

- ни одной карточки;
- одну карточку;
- несколько карточек;
- все 6 карточек.

Нулевой выбор является валидным ответом. Поэтому `Далее` всегда доступна после входа на вопрос.

После 7-го вопроса кнопка называется `Показать результаты`.

### 4.3. Редактирование

`Назад` возвращает на предыдущий вопрос без потери выбора.

На итоговом экране `Назад к ответам` возвращает к 7-му вопросу с сохранением всей анкеты.

`Пройти заново` очищает название компании и все ответы и возвращает на стартовый экран.

## 7. Правила подсчёта

Каждый выбранный вариант даёт соответствующему типу `+1`.

Для каждого типа:

`Score = количество вопросов, в которых выбран вариант этого типа)`

Диапазон: `0..7`.

Пользователь может выбрать один и тот же тип не более одного раза на вопрос, потому что на вопрос существует ровно одна карточка каждого типа.

Общее количество выбранных соответствий:

`TotalSelections = сумма Score по всем 6 типам`

Для листа `Итоги`:

`Share = Score / TotalSelections`

Если `TotalSelections = 0`, доля показывается как `0%`, а диаграмма-бублик не создаётся.

Сортировка итогов:

1. `Score` по убыванию;
2. при равенстве — исходный порядок типов из раздела 5.

Никаких искусственных мест или дополнительного tie-breaker нет.

## 8. UI и визуальное поведение

### 8.1. Окно

Базовый размер: около `1200×800`.

Интерфейс должен корректно работать на Windows 10/11 при системном масштабировании 100%, 125% и 150% и не требовать фиксированного разрешения.

### 8.2. Экран вопроса

Верхняя зона:

- `Корпоративная культура — <Компания>`;
- `Вопрос N из 7`;
- название вопроса;
- подсказка `Выберите все варианты, которые соответствуют вашей компании. Можно не выбирать ни одного.`

Основная зона:

- сетка 2×3;
- 6 карточек типов;
- вся карточка кликабельна.

Состояния карточки:

- выбранная: основной цвет типа, заметная рамка, символ `✓`;
- невыбранная: светлый фон типа;
- hover: визуальное усиление рамки;
- focus: видимый keyboard focus.

Клавиатура:

- `Tab` перемещает фокус;
- `Space` и `Enter` переключают карточку;
- основные кнопки доступны с клавиатуры.

Внизу:

- `Назад`;
- прогресс из 7 сегментов;
- `Далее` или `Показать результаты`.

### 8.3. Итоговый экран

Слева:

- 6 строк результатов;
- цвет типа;
- название;
- горизонтальная полоса;
- `x из 7`.

Справа:

- диаграмма-бублик при ненулевом результате;
- легенда по типам.

При полном нуле вместо диаграммы показывается сообщение `Нет выбранных соответствий`.

## 9. XLSX: лист «Выбранные опции»

Лист содержит полную матрицу 6×7, а не только выбранные значения.

Верхняя часть:

- `Типология корпоративных культур`;
- `Компания: <название>`;
- `Дата: <дата сохранения>`.

Таблица:

| Тип организации | Атмосфера | Система управления | Убеждения | Слоган | Лидер | Потребности сотрудника | Условия эффективности |
|---|---|---|---|---|---|---|---|

Строки идут в исходном порядке типов.

Оформление:

- выбранная ячейка: основной цвет типа;
- выбранный текст начинается с `✓ `;
- невыбранная ячейка: светлый фон типа;
- ячейка с названием типа остаётся достаточно насыщенной независимо от выбора;
- заголовки нейтрально-серые;
- перенос текста;
- вертикальное выравнивание по верхнему краю;
- границы ячеек;
- настроенные ширины столбцов и высоты строк;
- закреплены заголовок таблицы и первый столбец;
- печать в альбомной ориентации;
- fit to 1 page wide.

Выбранность должна быть понятна и при чёрно-белой печати за счёт `✓`.

## 10. XLSX: лист «Итоги»

Слева таблица:

| Тип организации | Совпадений | Доля |
|---|---:|---:|

Порядок — по правилам сортировки из раздела 7.

`Совпадений` — целое число `0..7`.

`Доля` — доля от общего количества всех выбранных соответствий, формат процента с одной цифрой после запятой, где это имеет смысл.

Справа диаграмма-бублик:

- 6 сегментов;
- цвета строго из раздела 5;
- заголовок `Профиль корпоративной культуры`;
- легенда с типами;
- данные диаграммы соответствуют итоговой таблице;
- диаграмма является частью XLSX, а не внешней картинкой.

Центральное значение бублика в приложении показывает `TotalSelections`. В XLSX центральное значение допускается реализовать как текстовый элемент поверх диаграммы, если Open XML реализация остаётся стабильной; отсутствие центрального текста не должно менять расчёт или данные диаграммы.

Если все результаты нулевые:

- таблица остаётся;
- диаграмма не создаётся;
- на месте диаграммы выводится `Нет выбранных соответствий`.

## 11. Ошибки и граничные случаи

### 11.1. Название компании

- пустое значение запрещено;
- ведущие и замыкающие пробелы удаляются;
- исходный текст сохраняется для отображения;
- имя файла санитизируется отдельно.

### 11.2. Сохранение файла

При ошибке записи — например, нет прав, файл заблокирован, путь недоступен — приложение:

- не завершается аварийно;
- показывает понятное сообщение;
- оставляет результаты в памяти;
- позволяет повторить сохранение в другое место.

Существующий файл не перезаписывается молча: стандартный диалог сохранения должен запросить подтверждение пользователя.

### 11.3. Нулевые ответы

Допустимы:

- 0 выборов в одном вопросе;
- 0 выборов во всех вопросах.

Это валидный результат, а не ошибка валидации.

## 12. Хранение и приватность

Приложение:

- не выполняет сетевые запросы;
- не отправляет телеметрию;
- не пишет в реестр;
- не использует `%AppData%` для состояния анкеты;
- не создаёт локальную БД;
- не сохраняет ответы автоматически.

Состояние живёт только в памяти до закрытия приложения.

Единственный постоянный пользовательский артефакт — XLSX, явно сохранённый пользователем.

## 13. Тестирование

### 13.1. Unit tests

Обязательно проверить:

- один выбор добавляет `+1` нужному типу;
- несколько типов в одном вопросе считаются независимо;
- 0 выборов допустим;
- все 42 карточки выбраны: каждый тип имеет `7`;
- стабильная сортировка при равных баллах;
- `TotalSelections`;
- расчёт `Share`;
- безопасное имя файла при специальных символах.

### 13.2. XLSX tests

Программно открыть созданный файл через Open XML SDK и проверить:

- файл валиден;
- ровно два листа;
- листы называются `Выбранные опции` и `Итоги`;
- значения компании и даты присутствуют;
- в первой таблице есть все 42 варианта;
- выбранные и невыбранные клетки имеют разные заливки;
- заливки соответствуют заданной палитре;
- выбранные клетки имеют `✓`;
- итоговые баллы корректны;
- при ненулевом результате есть chart part с donut chart;
- при полном нуле chart part не создаётся.

### 13.3. UI / smoke tests

Минимальный smoke-test должен подтверждать, что Release EXE запускается на Windows runner/тестовом Windows-хосте и стартовое окно создаётся без необработанного исключения.

Критические вычисления не должны тестироваться только через UI: они покрываются на уровне модели.

5. publish `win-x64`, self-contained, single-file;
6. публикацию `G-Spiral.exe` как workflow artifact.

Для тегов `v*` предусматривается GitHub Release с тем же EXE.

Сборка должна быть воспроизводимой из репозитория без ручного добавления файлов.

├─ tests/

├─ docs/
│  └─ superpowers/
│     └─ specs/

Лицензия проекта не влияет на архитектуру приложения и должна быть выбрана владельцем репозитория отдельно до публичного релиза, если потребуется явный `LICENSE`.

## 16. Не входит в v1.0

В первую версию не входят:

- многопользовательский режим;
- хранение истории опросов;
- база данных;
- облачная синхронизация;
- отправка результатов по почте;
- импорт предыдущих XLSX;
- настройка методики пользователем;
- серверная часть;
- macOS/Linux версии;
- installer/MSI;
- автоматическое обновление.

## 17. Критерии приёмки v1.0

Версия считается готовой, если одновременно выполнено следующее:

1. `G-Spiral.exe` запускается на Windows 10/11 x64 без установленного .NET Runtime и без Excel.
2. Пользователь вводит название компании и проходит все 7 вопросов.
3. В каждом вопросе можно выбрать от 0 до 6 карточек.
4. Навигация назад не теряет ответы.
5. Итоги по каждому типу находятся в диапазоне 0–7 и соответствуют выбранным карточкам.
6. Итоговый экран показывает отсортированные результаты и корректную диаграмму либо сообщение о полном нуле.
7. XLSX содержит ровно два требуемых листа.
8. Первая вкладка содержит полную матрицу методики с яркими выбранными и приглушёнными невыбранными клетками.
9. Вторая вкладка содержит отсортированные итоги и корректную диаграмму-бублик при ненулевых данных.
10. Цвета шести типов одинаковы в UI и XLSX.
11. XLSX открывается без предупреждения о повреждении файла в актуальном Microsoft Excel.
12. CI проходит успешно и публикует portable EXE.
13. Приложение не выполняет сетевых запросов и не сохраняет анкету без явного действия пользователя.
