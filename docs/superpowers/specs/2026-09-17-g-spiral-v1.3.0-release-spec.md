# G-Spiral 1.3.0 — Release Specification

**Дата:** 2026-09-17  
**Базовый релиз:** `v1.2.0`  
**Рабочая ветка:** `feature/v1.3.0`

## 1. Цель релиза

G-Spiral 1.3.0 исправляет обнаруженные проблемы 1.2.0 и уточняет методику опроса:

- одинаковые утверждения в рамках одного этапа показываются пользователю один раз, но могут начислять баллы нескольким скрытым типам;
- проценты на странице результатов становятся однозначными и понятными;
- 3D-круговая диаграмма должна выглядеть как настоящая объёмная диаграмма, а не как два наложенных круга;
- при переходе между этапами список всегда открывается сверху;
- приложение получает встроенную разноцветную спиральную иконку;
- устраняется ошибка восстановления содержимого XLSX в Microsoft Excel;
- отображаемые баллы округляются до целого;
- структура XLSX меняется на три листа в новом порядке и с новой иерархической детализацией.

## 2. Модель опроса и дедупликация вариантов

### 2.1. Семь этапов сохраняются

Опрос по-прежнему проходит строго по семи этапам-столбцам:

1. Атмосфера
2. Система управления
3. Убеждения
4. Слоган
5. Лидер
6. Какие потребности рядового сотрудника удовлетворяет
7. В каких условиях эффективна

В верхней части экрана сохраняются:

- `Вопрос N из 7`;
- название текущего этапа;
- прогресс по этапам.

### 2.2. Одинаковое утверждение показывается один раз

В 1.2.0 одно и то же атомарное утверждение могло встречаться в нескольких скрытых ячейках одного этапа и поэтому отображаться пользователю несколько раз.

В 1.3.0 на уровне отображения применяется дедупликация:

- варианты текущего этапа объединяются по нормализованному тексту;
- нормализация: trim, схлопывание повторных пробелов, сравнение без учёта регистра;
- семантически похожие, но не идентичные формулировки **не объединяются**;
- один отображаемый вариант хранит ссылки на один или несколько исходных hidden option IDs.

Пример:

`Регулярный менеджмент`

может быть показан пользователю один раз и одновременно относиться к типам `Успех` и `Правила`.

### 2.3. Начисление баллов при объединённом варианте

Выбор одного отображаемого варианта переключает в состояние `selected` все исходные hidden option IDs, которые в него входят.

Каждая исходная скрытая ячейка по-прежнему имеет максимум 100 баллов. Если в конкретной скрытой ячейке `N` исходных атомарных вариантов, вес одного варианта этой ячейки равен:

`100 / N`

Если один отображаемый вариант связан с несколькими скрытыми типами/ячейками, каждому из них начисляется **его собственный независимый вес**.

Таким образом дедупликация не меняет исходную математическую структуру 42 ячеек.

### 2.4. Рандомизация

- внутри каждого этапа отображаемые дедуплицированные варианты перемешиваются случайно;
- порядок создаётся один раз при начале прохождения;
- `Назад` / `Далее` не меняют порядок;
- `Пройти заново` создаёт новый порядок;
- цвет карточки не зависит от скрытого типа;
- название скрытого типа на этапе опроса нигде не отображается.

## 3. Результаты и проценты

### 3.1. Балл типа

Для каждого типа сохраняется точный внутренний score `0…700`.

В UI и XLSX балл отображается **округлённым до ближайшего целого** без изменения внутренней математики.

Примеры:

- `241.6667 → 242`
- `183.3333 → 183`
- `108.3333 → 108`

Округление для отображения: `MidpointRounding.AwayFromZero`.

### 3.2. Основной процент результата

Основной процент возле каждого типа показывает **выраженность типа относительно его собственного максимума 700 баллов**:

`ExpressionPercent = TypeScore / 700 × 100%`

Пример:

`425 / 700 · 60,7% выраженности`

Под заголовком блока результатов выводится пояснение:

> Процент показывает долю от максимально возможных 700 баллов для данного типа.

Итоги сортируются по убыванию точного score, при равенстве — по каноническому порядку типов.

### 3.3. Процент в круговой диаграмме

Круговая диаграмма показывает другой показатель:

`PieShare = TypeScore / Sum(AllTypeScores)`

Подпись диаграммы:

**Структура набранных баллов**

Подпояснение:

> Секторы показывают долю каждого типа в сумме набранных баллов.

Если сумма score равна нулю, диаграмма не отображается и выводится `Нет выбранных соответствий`.

## 4. Настоящая 3D pie chart

### 4.1. UI

Существующая имитация из двух кругов удаляется.

Новый custom WPF control строит настоящую псевдо-3D круговую диаграмму:

- верхняя поверхность каждого сектора;
- отдельные боковые поверхности видимых секторов;
- единая перспектива и эллиптическое сжатие по вертикали;
- боковые грани темнее верхней поверхности;
- белые/светлые разделители между секторами;
- порядок и цвета соответствуют отсортированным результатам;
- диаграмма масштабируется без искажений.

### 4.2. XLSX

На листе `Итоги` используется native Excel/Open XML 3D pie chart (`pie3DChart`) с корректными ссылками на данные и цветами типов.

Диаграмма не должна использовать приём «два наложенных круга».

## 5. Scroll-to-top при навигации

При каждом переходе:

- `Далее`;
- `Назад`;
- `Назад к ответам` с экрана результатов;

ScrollViewer этапа программно прокручивается в начало (`ScrollToTop`) **после** загрузки нового содержимого.

Положение прокрутки предыдущего этапа не переносится на следующий.

## 6. Иконка приложения

Добавить встроенную application icon в виде **разноцветной спирали**.

Требования:

- современная чистая геометрия;
- 6 основных цветов типов;
- хорошо читается в 16×16, 32×32, 48×48 и 256×256;
- используется в EXE, taskbar/window icon и окне `О программе`;
- исходный raster/vector asset хранится в репозитории;
- `.ico` содержит несколько размеров.

## 7. XLSX — исправление совместимости Microsoft Excel

### 7.1. Подтверждённый дефект 1.2.0

Microsoft Excel восстанавливает unreadable content в:

- `/xl/worksheets/sheet1.xml`
- `/xl/worksheets/sheet2.xml`

Сообщение Excel указывает на восстановление `Представление` (`sheetViews`).

### 7.2. Root cause

В 1.2.0 frozen panes сформированы с несогласованными `xSplit/ySplit`, `TopLeftCell` и `ActivePane`.

Для аудитной таблицы ожидаемая модель `B7` означает:

- `xSplit = 1` — заморожен первый столбец;
- `ySplit = 6` — заморожены первые шесть строк;
- `topLeftCell = B7`;
- `activePane = bottomRight`.

В 1.3.0 frozen panes должны строиться только через согласованные конфигурации.

### 7.3. Проверки

Добавить regression tests, которые проверяют XML каждого `sheetView`:

- `xSplit`;
- `ySplit`;
- `topLeftCell`;
- `activePane`;
- `state=frozen`;
- отсутствие конфликтующих pane/selection элементов.

Сохраняется Open XML Validator. Дополнительно тест распаковывает XLSX и проверяет структуру worksheet XML непосредственно.

## 8. XLSX — новая структура листов

Workbook содержит **ровно три листа в следующем порядке**:

1. `Таблица ответов`
2. `Итоги`
3. `Детализация ответов`

### 8.1. Лист 1 — «Таблица ответов»

Аудитная матрица 6 × 7.

Строки:

- Бирюза
- Возможности
- Успех
- Правила
- Сила
- Принадлежность

Столбцы — семь этапов.

В каждой ячейке:

- округлённый score скрытой ячейки `0…100`;
- список исходных атомарных утверждений;
- `✓` для выбранного;
- `○` для невыбранного.

Типы окрашены в канонические цвета.

Это первая вкладка, поскольку она является основной аудитной таблицей результата.

### 8.2. Лист 2 — «Итоги»

Таблица:

| Место | Тип | Баллы | Максимум | Выраженность |
|---|---|---:|---:|---:|

- `Баллы` — округлённый score;
- `Максимум` — 700;
- `Выраженность` — `score / 700`;
- сортировка — по убыванию точного score;
- рядом native 3D pie chart;
- рядом с графиком пояснение, что pie показывает долю типа в сумме набранных баллов.

### 8.3. Лист 3 — «Детализация ответов»

Иерархическая таблица, где движение слева направо увеличивает детализацию:

| Этап | Тип | Утверждение | Ответ |
|---|---|---|---:|
| Атмосфера | Бирюза | Можно свободно выражать творческие идеи | 1 |
|  |  | Самовыражение поощряется | 0 |
|  | Возможности | Можно экспериментировать | 1 |
| Система управления | Бирюза | ... | 1 |

Иерархия:

`Этап → Тип → исходное атомарное утверждение → 1/0`

Требования к оформлению:

- этап отображается один раз в начале блока;
- тип отображается один раз в начале подблока;
- визуальные отступы и границы подчёркивают уровень вложенности;
- этапы выделены нейтральными декоративными цветами;
- типы используют их канонические цвета;
- столбец `Ответ` содержит **только `1` или `0`**;
- `1` визуально выделен сильнее `0`;
- лист пригоден для последующего анализа и фильтрации;
- строки следуют исходной методической структуре, а не случайному порядку UI.

## 11. Тестирование и критерии приёмки

### 11.1. Модель

- exact duplicate в одном этапе отображается один раз;
- один display option может ссылаться на 2+ hidden options;
- его выбор начисляет корректный независимый вес каждому связанному типу;
- near-duplicate не объединяется;
- внутренние score не округляются преждевременно;
- display score округляется до целого;
- expression percent = score / 700;
- pie share = score / total selected score.

### 11.2. UI

- 7 этапов;
- дедуплицированные варианты без скрытых названий типов;
- декоративные цвета не кодируют тип;
- рандомизация стабильна внутри прохождения;
- новый restart создаёт новый порядок;
- переход на новый этап всегда открывает scroll сверху;
- 3D pie имеет отдельные боковые поверхности;
- `О программе` показывает версию 1.3.0, иконку и copyright.

### 11.3. XLSX

- ровно 3 листа в утверждённом порядке;
- Open XML Validator: 0 errors;
- sheetViews regression tests проходят;
- sheet1/sheet2 не содержат неконсистентных frozen pane settings;
- `Детализация ответов` содержит иерархию Stage → Type → Statement → 1/0;
- 3D pie присутствует только при ненулевой сумме score;
- score cells имеют отображение целым числом;
- XLSX открывается Microsoft Excel без recovery dialog.

### 11.4. Build/release

- все automated tests GREEN;
- `dotnet publish` GREEN;
- `G-Spiral.exe --smoke-test` exit code 0;
- PE/FileVersion = `1.3.0.0`;
- GitHub Release `v1.3.0` содержит `G-Spiral.exe`;
- release asset SHA-256 фиксируется в release notes/final report.

## 12. Не входит в 1.3.0

- сетевое хранение результатов;
- AD lookup ФИО;
- централизованная аналитика;
- изменение шести базовых типов;
- изменение семи этапов;
- изменение максимума 100 баллов на скрытую ячейку.
